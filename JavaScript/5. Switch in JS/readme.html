JavaScript Conditionals: if/else-if and switch — Part 7

Mental model: a conditional is a fork in the road. The ladder asks questions in order and takes the first "yes". A switch jumps straight to the exact matching label.

1. The if / else if / else ladder

const score = 50;

if (score >= 90) {
  console.log("A+");
} else if (score >= 80) {
  console.log("A");
} else if (score >= 70) {
  console.log("B+");
} else if (score >= 60) {
  console.log("B");
} else {
  console.log("Need to improve (or) Fail.");   // runs for 50
}

The >= 60 branch prints "B".

What I corrected

The class code printed "A" for 60 and above, a second time. That looks like a copy-paste slip, since the grades run A+, A, B+, B, and your switch prints "B" for 60. Please check it against what your teacher said.

  • Conditions are checked top to bottom. The first true one runs and the rest are skipped, so only one branch ever runs.
  • Order matters: go from strictest to loosest. If >= 60 came first, a 95 would print "B".
  • else means nothing above matched, and it's optional. Each condition is converted to a boolean (truthy/falsy, Part 2).

Ladder = first "yes" wins, so go from strictest to loosest.

2. switch

const score = 81;

switch (score) {
  case 90:
    console.log("A+");
    break;
  case 80:
    console.log("A");
    break;
  case 70:
    console.log("B+");
    break;
  case 60:
  case 50:
    console.log("B");
    break;
  default:
    console.log("Need to improve (or) Fail.");
}

case 70 ends with break, and the stray text after the closing brace is gone.

What I corrected
  • The class code had no break after case 70, so a 70 would print "B+" and then "B" (fall-through). If it was left out on purpose to demonstrate fall-through, that's the demo. For grading, you'd want the break.
  • } (for switch cases). after the closing brace is a syntax error, so I removed it.
  • switch (score) is evaluated once and compared to each case with strict equality (===, Part 3). case 80 matches only exactly 80, and case "80" wouldn't match the number 80.
  • With score = 81, nothing matches, so the output is the default message, even though 81 is a good mark.
  • break leaves the switch. It's the same keyword as in loops (Part 4), but here it exits the switch. Without it, execution falls through into the next case's code, whether that case matches or not.
  • Stacked cases like case 60: and case 50: are deliberate fall-through, so both share one block.
  • default means nothing matched (like else), and it usually goes last.

switch = jump to the matching label, then run until break.

3. Which one to use

  • Use a ladder for ranges and conditions (>=, &&, and so on).
  • Use switch for exact values, like menu options or day names.

The two blocks in class aren't equivalent. At 81, the ladder gives "A" but the switch falls to default. At 50, the ladder says Fail but the switch prints "B". The cause is that switch only matches exact values.

Mental model

Both forks run only one path. The ladder tests conditions from top to bottom and takes the first true one, so it handles ranges. The switch evaluates once and jumps to the case that matches exactly (===), then keeps running until it hits a break. A missing break causes fall-through, and default or else catches everything unmatched.
