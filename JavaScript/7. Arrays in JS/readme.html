JavaScript Arrays — Part 5

Mental model: an array is a numbered row of boxes (starting at 0) that can hold anything. Most methods change it in place, and a few hand back something new.

1. Creating and reading

const arrName = ['Suresh', 'Mukesh', 'Rakesh', true, 123,
  function dummyFunc() { console.log("Dummy function"); },
  { name: 'Pratham', age: 21 }];

Indexing always starts at 0.

What I corrected

The class code wrote arrName = [...] with no let or const, which creates an accidental global (Part 1). The note also said indexing starts at 0 "by default", but it always starts at 0 and you can't change that.

arrName[1]          // 'Mukesh'
arrName.length      // 7
typeof arrName[6]   // "object"

Arrays can mix any types. length is the number of items, which is the last index plus 1. typeof reports the type of the value stored there (Part 2), so index 6 gives "object" and index 5 would give "function".

Array = numbered lockers, starting at 0.

2. Same array, not a copy

const newArr = arrName;     // shares the SAME array
newArr[1] = 'Pratham';
console.log(arrName[1]);    // 'Pratham', both names see it
const copy = [...arrName];  // a real (shallow) copy

newArr = arrName copies the reference, not the array.

What I corrected

The class heading called this "Reassignment" and the comment said arrName "should still show" Pratham. Nothing was reassigned. newArr[1] = ... changes an element (mutation), and arrName shows 'Pratham' because both names point at one array. Also, a const array can still be mutated (Part 1). arrName.slice() is another way to copy.

Two names, one array. To get a second array, copy it.

3. Searching: indexOf, includes

newArr.indexOf("Suresh")    // 0   (first match; -1 if not found)
newArr.includes("Rakesh")   // true

Both compare with strict equality, so they're case-sensitive and "1" doesn't match 1. -1 means "not found", which the class comment didn't mention.

4. Adding and removing at the ends

newArr.push("Laptop");      // add to end
newArr.unshift("Laptop");   // add to start
newArr.pop();               // remove last
newArr.shift();             // remove first
What I corrected

The class code had pop(""). pop takes no arguments, so the "" was silently ignored. Write pop().

push and unshift return the new length. pop and shift return the removed item. All four change the original array.

push/pop work at the end. unshift/shift work at the start.

5. sort

marks.sort();                  // sorts as TEXT by default
marks.sort((a, b) => a - b);   // numeric, small to big
marks.sort((a, b) => b - a);   // numeric, big to small

sort() with no function sorts alphabetically, not numerically.

What I corrected

The class treated sort() as a numeric sort. Your marks came out in the right order only because every value has two digits. [5, 100, 25].sort() gives [100, 25, 5]. sort also changes the original array in place.

No compare function = dictionary order, not number order.

6. slice(start, end)

marks.slice(2, 4)   // [50, 80]  (indexes 2 and 3)

Start is included, end is excluded, so slice(2, 4) returns two items.

What I corrected

The class comment said "index 2 to before 6", but the code is slice(2, 4). It returns indexes 2 and 3, which is [50, 80] for your unsorted marks. slice returns a new array and leaves the original alone, and slice() with no arguments is a quick copy.

slice = photocopy a piece, original untouched.

7. Which methods change the array?

  • Changes the original: push, pop, shift, unshift, sort.
  • Leaves it alone: slice, indexOf, includes.

If you need the original afterwards, copy first with [...arr] or arr.slice().

Mental model


An array is a numbered row of boxes starting at 0. Reading uses arr[i], and searching uses indexOf and includes. Adding and removing happens at the ends. slice takes a piece without touching the original. sort changes the array in place and needs a compare function for numbers. b = a shares one array, so copy with [...a] when you need a separate one.
