JavaScript Operators — Part 3

Mental model: operators are verbs that act on values. They do math, change a variable, compare two values, or combine true/false answers.

1. Arithmetic

2 + 69    // 71    addition
2 - 69    // -67   subtraction
2 * 69    // 138   multiplication
69 / 2    // 34.5  division
69 % 2    // 1     remainder
2 ** 3    // 8     exponent
Corrections
  • "substaction" should be "subtraction", and / was missing from the list.
  • % gives the remainder, so 2 % 69 is 2, which is what a%b printed. Calling it "modulus" is loose, because they differ for negatives (-5 % 3 is -2).
  • The parentheses in (a**b) aren't needed.

% = what's left over. Use case: n % 2 === 0 checks for an even number.

2. Increment and decrement

x++ means x = x + 1, and x-- means x = x - 1. On a line by themselves, pre and post behave the same. The difference only shows when you use the value in an expression:

let a = 10;
console.log(a++);   // prints 10, then a is 11
let b = 10;
console.log(++b);   // prints 11, b is 11
Corrections
  • The comment says a is incremented "after console.log runs". Actually the increment happens while a++ is being evaluated, before console.log runs. The expression just hands back the old value.
  • The pre-increment and pre-decrement comments say a, but the variable is b.
  • Each section redeclares let a. That's fine while commented out, but running them together breaks (same let name twice in one scope, from Part 1).

x++ hands you the old value, then bumps. ++x bumps, then hands you the new value.

3. Assignment and shorthand

a += b;    // a = a + b
a -= b;  a *= b;  a /= b;  a %= b;  a **= b;

= assigns (stores the right side into the left). It doesn't compare, and if (a = 5) is a classic bug. Shorthand needs let, since const can't be reassigned. With strings, += appends.

a += b = "update a using b".

4. Comparison: == === != !==

69 == 69      // true
69 === 69     // true
69 == '69'    // true    == converts types first
69 === '69'   // false   === does not
Correction

== doesn't just "expect values to be the same". It first converts both sides to a common type, then compares (loose equality). So 0 == false, '' == 0, and null == undefined are all true. === needs the same type and the same value.

The class examples used two numbers, so == and === always matched. The difference only shows in a == c with c = '69', which wasn't run. Default to ===.

!= and !== are the same checks flipped. The "NOT gate" idea from class is right.

=== asks "same type AND same value?" == asks "same value after converting?"

5. Logical: && || !

aca && ca || c!a
truefalsefalsetruefalse
  • && is true only if both sides are true.
  • || is true if at least one side is true.
  • ! flips the value.

Gotcha: && and || return one of the operand values, not always a boolean. They also stop early (short-circuit).

0 && 5        // 0        stops at the first falsy
"hi" && 5     // 5        all truthy, returns the last
0 || "guest"  // "guest"  returns the first truthy

! converts to boolean first, so !"hi" is false, and !!x is the same as Boolean(x).

&& = both must pass. || = any one passes. ! = flip.

Mental model

Arithmetic produces numbers, and ++/--/+= change a variable in place. Comparison (===, ==) produces a boolean, and logical operators combine those booleans. Two rules to remember: "post gives old, pre gives new" and "use ===, because == converts types first".
