JavaScript Variables and Data Types — Part 1

Mental model: a variable is a labeled box holding a value. The keyword (let, const, var) decides what you can do to the label, and where it can be seen.

1. Data types: string, number, boolean

let name = "Rohan";         // string: text in quotes
let age = 28;               // number
let eligibleToVote = true;  // boolean: true / false

Number is 64-bit floating point, so it covers integers and decimals. Special values: NaN ("not a valid number", but its type is still number) and Infinity. Check any type with typeof age.

Corrections
  • let age = "28" is a string, because the quotes make it text. "28" + 2 gives "282", while 28 + 2 gives 30.
  • "floating pint" should be "floating point".

Quotes = string. No quotes = number or boolean.

2. Statements and console.log

  • ; ends a statement. It's optional because JS inserts it for you, but keep it: a line starting with ( or [ can break without it. Your note called it a "separator", but it's a terminator.
  • Indentation is only for humans.
  • console.log(a, b) prints each argument separated by a space.
  • console.log(sum)ff; had stray characters and is a syntax error. Removed.

3. let, const, var

let a = 1;  a = 2;        // ✅ reassign
const b = 1; b = 2;       // ❌ TypeError
var c = 1;  var c = 2;    // ✅ even redeclare (messy)
Corrections
  • const isn't "immutable". The variable can't be reassigned, but an object or array it holds can still change.
  • In the const example, the reassignment throws a TypeError before console.log runs, so nothing prints, not "Pratham".
  • collage vs college is a typo. Assigning to an undeclared name creates an accidental global in normal mode.

Use const by default, let when you must reassign, and avoid var.

const = a tag glued to a value. let = a tag you can move. var = an old tag with loose rules.

4. Scope: where a variable can be seen


let and const are block-scoped: they live inside the nearest { }. var is function-scoped: it ignores blocks and only respects the function wall. Your note said let is "local scope", which is too vague. Block scope is the precise term.


function f() {
  if (true) { let a = 1; var c = 2; }
  console.log(c); // 2
  console.log(a); // ReferenceError
}


let and const respect { } walls. var only respects function walls.

Correction

Case-sensitivity and redeclaring are separate ideas. What fails is declaring the exact same name twice in the same scope. That's an error for let and const, but var allows it.



Mental model


The data type tells you what the value is. The keyword tells you whether the name can be reassigned (let yes, const no) and how far it can be seen (let and const inside a block, var across the function). Pick const first, let if it must change, and skip var.
