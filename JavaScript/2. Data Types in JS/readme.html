JavaScript Dynamic Typing and Type Conversion — Part 2

Mental model: in JS the value carries the type, not the variable. Conversions create new values and never change the original unless you store them.

1. Dynamic typing

let a = 123;   // number
a = "demo";    // now a string
a = false;     // now a boolean

In C/Java-style languages, int a = 23; locks the type. In JS, let a can hold anything, and typeof a reports the type of whatever is inside right now.

Variable = a reusable box. The type lives on what's inside.

2. undefined vs null

  • let b; gives undefined: declared, nothing assigned yet.
  • let sum = null; gives null: you deliberately say "empty".
  • Gotcha: typeof null is "object". That's an old quirk, and it doesn't mean null is an object.

typeof is an operator, not a function. typeof sum is enough, and in typeof(sum) the parentheses are just grouping.

3. The + surprise

12 + 1      // 13
'13' + 1    // "131"  a string is involved, so + glues
'13' - 1    // 12     - * / always convert to numbers

This is implicit conversion (coercion): JS converts for you, sometimes unexpectedly.

+ with any string = glue. Other math operators = numbers.

4. Explicit conversion

let abc = 123;
String(abc);                // returns "123", but the result is thrown away
console.log(typeof abc);    // still "number"
let result = String(abc);   // ✅ store it in a new variable
abc = String(abc);          // ✅ or reassign the same variable
Corrections
  • String(abc) doesn't convert abc "for that line". It never touches abc. It returns a new value, and you have to store it.
  • The point isn't "declaration and initialization". It's assignment. abc = String(abc) is reassignment, which works with let but fails with const.
  • The logs say "name of abc" but print the value.

String to number:

Number("13")        // 13
Number("12.5")      // 12.5
Number("")          // 0   (empty string)
Number("Inspiria")  // NaN
Number("12px")      // NaN
Correction

It's not "letters can't convert". The whole string must be a valid number, so "12px" fails too. NaN means "not a valid number", but typeof NaN is still "number". Since NaN !== NaN, test it with Number.isNaN(x).

Number() is all-or-nothing.

5. Boolean conversion: truthy and falsy

Correction

It isn't just "whole numbers other than 0". Any non-zero number is true, including negatives and decimals (-5, 0.5).

The falsy values you'll meet are false, 0, "", null, undefined, and NaN. Everything else is truthy.

Gotcha: "0", "false", and [] are all truthy, because a non-empty string and any array count as truthy.

Falsy = zero, empty, or nothing. Everything else is truthy.

Mental model

The value carries the type, so a variable can switch types freely. JS sometimes converts for you (+ glues if any side is a string, other math operators force numbers). When you convert on purpose, String(), Number() and Boolean() each return a new value, and you must store it or it's lost. Number() is strict, giving NaN unless the whole string is numeric, and Boolean() is false only for the falsy values.
