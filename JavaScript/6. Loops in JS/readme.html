JavaScript Loops — Part 4

Mental model: a loop repeats a block of code while a condition stays true. for, while and do...while are three ways to write the same idea.

1. for

for (let i = 18; i > 0; i--) {
  console.log("Pratham", i);   // prints 18 down to 1
}

The brackets hold three parts: init; condition; update. The order is:

  1. init runs once.
  2. The condition is checked.
  3. The body runs.
  4. update runs.
  5. The condition is checked again, and so on, until it's false.

Your i > 0 prints 18 down to 1, and 0 is never printed. let i only exists inside the loop (block scope, Part 1). In the editor snippet, array is just a placeholder, and index < array.length loops over every position of an array.

for = a counter loop: where to start, how long to keep going, how to step.

2. while

let count = 0;
while (count <= 5) {
  console.log(count);   // 0, 1, 2, 3, 4, 5
  count++;
}

The condition is checked before each round, so the body may never run. Something inside must change the condition, or you get an infinite loop. Because <= includes 5, this prints six values, so watch for off-by-one.

while = "keep going as long as this is true".

3. do...while

let count = 0;
do {
  if (count === 0) {
    console.log("This is the first iteration");
  } else {
    console.log("Other iterations");
  }
  count++;
} while (count < 5);   // note the ; here
What I corrected

The class code used count == 0. I changed it to ===, which is the safer default (Part 3). Both give the same result here because both sides are numbers.

The body runs first and the condition is checked after, so it always runs at least once, even if the condition is false from the start.

do...while = do first, ask later.

4. break and continue

let count = 0;
while (count < 10) {
  count++;
  if (count === 2) {
    continue;   // skip the rest of this round
  } else if (count === 8) {
    break;      // leave the loop
  }
  console.log(count);   // prints 1 3 4 5 6 7
}

break exits the nearest loop only, and continue skips to the next round of the nearest loop.

What I corrected

The class comment said break "completely exits loop". In nested loops it only exits the innermost one, and outer loops keep going.

Gotcha: in your while, count++ comes before continue. If it came after, count would stay at 2 forever, which is an infinite loop. In a for loop, continue still runs the update, so that trap doesn't exist.

continue = skip this lap. break = leave the track.

5. Which loop to use

  • for when you know how many times (or you're walking through positions).
  • while when it depends on a condition and may run zero times.
  • do...while when it must run at least once.

Mental model


Every loop is a condition, a body, and something that eventually makes the condition false. for packs start, condition, and step into one line. while keeps only the condition. do...while checks the condition after the body, so it runs at least once. continue skips the rest of this round, and break leaves the nearest loop.
